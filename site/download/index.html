Install

Install steps for your system.

  1. Run the setup

    Double-click {{file.windows.name}}. It installs for your user only, so it does not ask for administrator rights.

  2. If SmartScreen stops it

    Windows may show "Windows protected your PC" for an installer that is not code-signed. Choose More info, then Run anyway.

  3. Choose what to link

    Tick Link every MCP client found to connect them now; it is off by default. Otherwise connect clients later on the app's MCP Servers page, or with latch setup. The setup can also add latch to your PATH for new terminals.

  4. Restart your MCP clients

    Restart each client you connected. LatchVerify starts in the tray and from the Start menu.

Silent install, for scripts (PowerShell) 
.\{{file.windows.name}} /VERYSILENT /SUPPRESSMSGBOXES /TASKS="linkclients,addtopath"

Without /TASKS a silent install links nothing. If linking does not finish, the details are in %LOCALAPPDATA%\Programs\LatchVerify\setup.log.

  1. Install the package

    In the folder you downloaded it to:

    bash 
    {{file.deb.cmd}}

    The package creates the latch.lock of the user who ran sudo and lists their MCP clients. It connects none.

  2. Connect your clients

    As yourself, not root, run latch setup and choose which clients to connect. Then restart them.

To uninstall: sudo apt remove latchverify. Every client gets its original commands back first.

  1. Install the package

    In the folder you downloaded it to:

    bash 
    {{file.arch.cmd}}

    Name the one file rather than a pattern such as latchverify-bin-*.pkg.tar.zst: with an older download in the same folder, the pattern matches both and pacman stops with duplicate target.

  2. Connect your clients

    As yourself, not root, run latch setup and choose which clients to connect. Then restart them.

To uninstall: sudo pacman -R latchverify-bin. Prefer to build it yourself? The install guide has the makepkg steps.

  1. Unpack and run the installer

    bash 
    {{file.tarball.cmd}}

    It installs to ~/.local/lib/latchverify, puts latch in ~/.local/bin, adds a menu entry and runs latch setup, which asks in your terminal which clients to connect. Set PREFIX=/some/dir to install somewhere else.

  2. Restart the clients you connected

    Run install.sh from a newer archive to update.

The bundled Node.js needs glibc 2.28 or newer (Debian 10, Ubuntu 20.04, RHEL 8 and later). The app needs unprivileged user namespaces, since the archive has no setuid sandbox helper. To uninstall: ~/.local/lib/latchverify/uninstall.sh.

There is no macOS package yet. On macOS, or anywhere you would rather build it, you need Node.js 22 or newer, pnpm and git.

bash 
git clone https://github.com/ANI-CPU-tech/LatchVerify.git
cd LatchVerify
corepack enable
pnpm install
pnpm build
pnpm link --global
latch setup

pnpm link --global puts latch on your PATH. A source checkout never updates itself: git pull and build again. More in the setup guide.

After installing

Connect the clients you want protected.

Connect from the app's MCP Servers page, or from a terminal. A connected client's stdio servers start behind the proxy, and their tools are pinned the first time the client starts them.

Linking commands
Command What it does
latch setupList the clients found and ask which to connect. Without a terminal it only lists them.
latch setup --client cursorConnect one client without asking.
latch setup --allConnect every client found.
latch setup --dry-runShow what would change, without writing anything.
latch setup --remove --client cursorDisconnect a client: its servers get their original commands back. --remove --all for every client.
latch watchKeep connected clients linked and show desktop notifications, on a machine without the app.

Where your latch.lock lives

Windows
%APPDATA%\LatchVerify\latch.lock
Linux
~/.config/latchverify/latch.lock
macOS
~/Library/Application Support/LatchVerify/latch.lock

latch review and latch verify open it from any directory. Inside a project with its own committed latch.lock, they use the project's file instead.

On Windows, the files shown under ~/.config are under %APPDATA% instead, except OpenCode's; the rest are in your user folder.

A config that exists but cannot be read is reported and left untouched. Project files teams commit, such as .mcp.json, are never rewritten.

Checksums

Check a download.

Every release publishes a SHA256SUMS file. Put it next to your download and run the check; it should print OK for your file. The SHA-256 of each file is also listed above.

Linux 
sha256sum -c SHA256SUMS --ignore-missing
Windows (PowerShell) 
Get-FileHash .\{{file.windows.name}}

Updates

It updates itself, with your say-so.

The app checks once a day. Settings → Updates shows the release notes and installs on one click; on the deb and Arch packages your system asks for your password. Each update is checked against the release's ed25519 signature and its SHA-256 before it runs. Your latch.lock and approvals are kept.

From a terminal
latch update, or latch update --check to only report
Windows, by hand
Run the newer setup
Debian, Ubuntu
sudo apt install ./latchverify_<new-version>_amd64.deb
Arch, CachyOS
sudo pacman -U latchverify-bin-<new-version>-1-x86_64.pkg.tar.zst
Portable archive
Run install.sh from the new archive

Uninstall

Leaving puts everything back.

Every way of uninstalling gives each MCP client its original server commands back first. Your latch.lock and settings stay, so a reinstall keeps your approvals.

Windows
Settings → Apps → Installed apps → LatchVerify
Debian, Ubuntu
sudo apt remove latchverify
Arch, CachyOS
sudo pacman -R latchverify-bin
Portable archive
~/.local/lib/latchverify/uninstall.sh
Any Linux install
The app's Settings → Uninstall LatchVerify, or latch uninstall --yes
